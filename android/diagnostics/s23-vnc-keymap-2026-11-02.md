# S23 graphical startup failure, 2026-11-02

Owner-provided screenshot from a Galaxy S23 after installing the Milestone D
debug APK. The display is black; the guest serial pane is empty. Host diagnostics
show the genuine QEMU backend exiting during VNC startup:

```text
libqemu-system-arm.so: -vnc unix:/data/user/0/org.qemu.android.dev/files/vnc.sock: could not find keymap file for language 'en-us'
Host: Connection reset by peer
Host control error: VM not running
```

The same error appears again after another Start attempt. It is a missing QEMU
runtime data file, not evidence that the Linux guest booted or that the software
renderer failed. The Android build packaged the QEMU executable but did not
package `pc-bios/keymaps/en-us`; host QEMU had its own installed map during the
successful Linux fixture test. See `ui/vnc.c`, `ui/keymaps.c` and `util/datadir.c`
for the path from VNC default layout to QEMU's `-L/keymaps/en-us` lookup.

Correction: stage the exact upstream keymaps in APK assets through Actions,
extract them into app-private runtime storage before starting the process,
pass that directory through `-L`, and make APK validation compare every packaged
map to the fork checkout. An ARM64 instrumentation smoke test initializes the
real backend's VNC server against those packaged assets when a device runner is
available. Kotlin runtime-data tests cover layout, invalid names and atomic
replacement. CI and S23 retest remain pending.
