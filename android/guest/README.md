# ARM Linux boot fixture

This fixture is for the first genuine guest boot, not Android 4.1 or OUYA.
It contains an ARMv7 Linux kernel, BusyBox initramfs and a pristine 64 MiB ext4
raw disk. Buildroot is pinned to the exact source commit in sources.json;
its source hashes (including Linux 6.18.7) are enforced. No firmware or games
are included. Corresponding sources/licences are uploaded as separate evidence.

The **ARM Linux guest fixture** Actions workflow builds the fixture and runs
two host QEMU ARM virt boots. It requires real kernel output, userspace startup,
disk write/read persistence across boots and poweroff. The downloadable disk
is pristine; tests modify a separate copy. Host checks validate the fixture,
not the Android-packaged QEMU binary. No local build is needed.

## When the fixture workflow passes

Download and extract its QEMU-Android-Linux-fixture artifact. In the Android app,
use a test VM with 512 MiB RAM and 2 CPUs, then import:

- kernel.zImage into the kernel slot.
- initramfs.cpio.gz into the initrd slot.
- disk.raw into the disk.raw slot. This replaces that VM's disk; use a test VM.

Start the VM. The real guest should print Linux kernel messages followed by
QEMU-ANDROID-USERSPACE, PERSIST-WRITTEN and QEMU-ANDROID-SHUTDOWN, then power off.
Start the same VM again without reimporting the disk. It should print
PERSIST-READ instead of PERSIST-WRITTEN, then shut down. The app stores a private
copy of imported images, so reimporting the pristine disk resets this test.
No guest messages are generated by the frontend.

Capture the guest serial text and the separate host diagnostics if boot fails.
Do not mark Android boot verified until these messages actually appear on the
phone. VM creation alone does not verify the native backend.

## Scope and licences

Buildroot metadata and legal-info sources accompany the artifacts. Linux and
BusyBox retain their original licences and notices. The custom init script is
GPL-2.0-or-later. The fixture uses a static musl toolchain and no guest network
interface. It is an automated test environment, not a general-purpose secure
Linux distribution; hashes/package provenance are not vulnerability clearance.
Do not put valuable data or secrets into its disposable test disk.

## Graphical fixture mode

The updated kernel includes built-in virtio GPU, framebuffer console and evdev /
virtio input drivers. A small GPL-2.0-or-later guest program writes color bars
through Linux `/dev/fb0`, logs real keyboard/tablet events and redraws the top
band when a key/button is pressed. It is a framebuffer test, not a desktop.

With the matching new APK, enable **Software guest display and input** before
Start. Graphical mode prints `QEMU-ANDROID-GRAPHICS` and `DISPLAY-READY`, then
stays running instead of immediately shutting down. **Guest shutdown** sends
the virtual power button; the program exits and init powers off. With graphics
disabled, the original two-boot persistence test still powers off automatically.
Older images do not contain this program/drivers and must be replaced in a
separate test VM. See [display instructions](../DISPLAY.md) for controls and
required phone evidence.

Actions also runs a third, graphical host boot and saves before/after real guest
frames, evdev serial events and shutdown results in the evidence artifact.
These host checks do not verify the Android display or physical controller.
